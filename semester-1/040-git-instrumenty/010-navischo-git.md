# Навіщо потрібен Git. Встановлення

**Блок:** Блок 4. Git та інструменти розробника
**Код заняття:** `040-git-instrumenty/010-navischo-git.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
Ідея систем контролю версій (version control).

## Мета заняття
- Розуміти, навіщо потрібна система контролю версій і яку проблему вона вирішує
- Встановити Git на свій комп'ютер і виконати початкове налаштування
- Знати, що таке GitHub і чим він відрізняється від самого Git

## Підготовка викладача (перед заняттям)
- Розіслати інструкцію зі встановлення Git студентам за 2–3 дні до заняття (за тим самим принципом, що й з JDK/IntelliJ у блоці 1) — заощадить час на самому занятті.
- Мати напоготові інсталятор Git на флешці — на випадок повільного інтернету в аудиторії.

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Запитати групу: «Хто хоч раз називав файли на кшталт `проект_фінал.docx`, `проект_фінал2.docx`, `проект_ФІНАЛ_реально_останній.docx`?» — майже завжди хтось усміхнено підніме руку. Показати: саме цю проблему — як зберігати історію змін файлу, не плодячи копії вручну — і вирішує система контролю версій.

### 2. Коротка теорія (15–20 хв)
**Що таке система контролю версій (version control system).** Інструмент, що зберігає ПОВНУ історію змін файлів проєкту: хто, коли і що саме змінив, з можливістю повернутись до будь-якої попередньої версії. На відміну від ручного копіювання файлів, система контролю версій зберігає лише РІЗНИЦЮ між версіями — компактно і зі зручним переглядом, що саме змінилось.

**Git.** Найпопулярніша система контролю версій у світі, створена 2005 року Лінусом Торвальдсом (автором ядра Linux) саме для потреб розробки Linux. Працює локально на комп'ютері розробника — не вимагає інтернету для щоденної роботи (комітів, перегляду історії, створення гілок).

**GitHub — це НЕ Git.** Git — сама технологія контролю версій. GitHub — окремий сервіс (сайт), що зберігає Git-репозиторії "в хмарі" й додає зручні інструменти для командної роботи: перегляд коду у браузері, обговорення змін, Pull Request'и (заняття 050). Є й інші подібні сервіси (GitLab, Bitbucket) — принципи ті самі, GitHub просто найпоширеніший.

**Навіщо це реальному розробнику.** Практично 100% Java-вакансій (і будь-яких інших) вимагають впевненого володіння Git — це не "додаткова навичка", а базовий інструмент щоденної роботи, як клавіатура.

### 3. Демонстрація / встановлення (основна частина заняття)

#### Крок 1. Встановлення Git (Windows)
1. Перейти на [git-scm.com/downloads](https://git-scm.com/downloads).
2. Завантажити інсталятор для Windows (сайт сам визначить ОС).
3. Запустити завантажений `.exe`-файл.
4. У майстрі встановлення можна залишити майже всі опції за замовчуванням. Один пункт вартий уваги: на кроці вибору редактора за замовчуванням (default editor) можна обрати звичний варіант (наприклад Notepad) замість Vim, якщо група ще не знайома з термінальними редакторами — це вплине лише на те, який редактор відкриється для написання повідомлень комітів у рідкісних випадках.
5. Натискати "Next" → "Install" → "Finish".

#### Крок 2. Перевірка встановлення
1. Відкрити термінал: у Windows — "Git Bash" (з'явиться в меню Пуск після встановлення) або звичайний командний рядок.
2. Ввести `git --version`.
3. Має з'явитись щось на кшталт `git version 2.47.0.windows.1`.

#### Крок 3. Початкове налаштування (обов'язково, один раз)
Git повинен знати, від чийого імені записувати коміти:
```
git config --global user.name "Ваше Ім'я"
git config --global user.email "your.email@example.com"
```
**Порада, яка заощадить плутанину надалі:** одразу встановити назву гілки за замовчуванням "main" (сучасний стандарт, який використовує GitHub), інакше `git init` може створити гілку "master" замість "main" залежно від версії й налаштувань Git:
```
git config --global init.defaultBranch main
```

### 4. Керована практика (20–30 хв)
Кожен студент встановлює Git і виконує початкове налаштування за кроками вище; викладач і ті, хто вже впорався, допомагають іншим. Перевірити результат командою `git config --list` — має вивести встановлені `user.name`, `user.email`, `init.defaultBranch`.

### 5. Самостійна практика / челендж (20–30 хв)
Зареєструвати акаунт на [github.com](https://github.com), якщо ще не зроблено на занятті 010 у блоці 1 (перевірити разом з групою, в кого вже є акаунт). Обрати нейтральне, професійне ім'я користувача — воно може з'явитися в резюме.

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: чим сьогоднішня тема відрізняється від того, що вивчали раніше (уперше йдеться не про синтаксис мови програмування, а про робочий процес та інструмент, яким користуються цілі команди). Анонсувати наступне заняття: перші реальні git-команди на практиці.
