# GitHub. Віддалені репозиторії

**Блок:** Блок 4. Git та інструменти розробника
**Код заняття:** `040-git-instrumenty/040-github-viddaleni-repozytorii.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
remote, push, pull, clone.

## Мета заняття
- Розуміти різницю між локальним репозиторієм (на комп'ютері) і віддаленим (на GitHub)
- Вміти створити репозиторій на GitHub і підключити до нього локальний проєкт
- Вміти `push`, `pull`, `clone`

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Запитати: «А що, якщо ваш ноутбук зламається прямо зараз — де лишиться весь код, над яким ви працювали?» Дотепер уся історія git жила лише локально, на одному комп'ютері. GitHub — резервна копія "в хмарі" плюс спосіб показати код будь-кому.

### 2. Коротка теорія (15–20 хв)
**Віддалений репозиторій (remote).** Копія репозиторію, що зберігається на сервері (GitHub), а не лише на локальному комп'ютері. Один локальний репозиторій може бути підключений до віддаленого під умовною назвою `origin` (стандартна назва за замовчуванням, не обов'язкова, але прийнята повсюдно).

**Команди:**
```
git remote add origin <URL-репозиторію>   # підключити віддалений репозиторій
git push -u origin main                    # відправити коміти на GitHub (-u запам'ятовує зв'язок гілки для наступних push)
git push                                   # наступні відправлення - вже без -u
git pull                                   # забрати нові зміни з GitHub у локальний репозиторій
git clone <URL-репозиторію>                # СКОПІЮВАТИ весь репозиторій з GitHub на новий комп'ютер
```

**`clone` проти `pull`.** `clone` виконується ОДИН РАЗ — щоб отримати репозиторій, якого ще немає локально (наприклад, на новому комп'ютері або коли приєднуєшся до чужого проєкту). `pull` виконується РЕГУЛЯРНО — щоб оновити вже існуючу локальну копію новими змінами з GitHub.

**Важлива практична деталь (перевірено на практиці).** Локальний `git init` може за замовчуванням створювати гілку `master`, тоді як GitHub при створенні репозиторію через сайт завжди називає основну гілку `main`. Якщо на занятті 010 виконали `git config --global init.defaultBranch main` — цієї плутанини не буде; якщо ні — варто перейменувати гілку перед першим `push` командою `git branch -M main`.

### 3. Демонстрація / live-coding (15–20 хв)
**Крок 1. Створення репозиторію на GitHub:**
1. Увійти на [github.com](https://github.com).
2. Натиснути "+" у верхньому правому куті → "New repository".
3. Ввести назву (наприклад `java-calculator`).
4. Залишити репозиторій публічним (Public) або приватним (Private) — на власний розсуд.
5. **НЕ** позначати "Add a README file" — репозиторій уже існує локально, порожній віддалений репозиторій легше підключити без конфліктів.
6. Натиснути "Create repository".
7. GitHub покаже сторінку з готовими командами — саме їх і виконати далі.

**Крок 2. Підключення й перше відправлення (наживо, з уже існуючим локальним репозиторієм із занять 020–030):**
```
git remote add origin https://github.com/ВАШ_ЛОГІН/java-calculator.git
git branch -M main
git push -u origin main
```
Оновити сторінку репозиторію в браузері — показати, що код з'явився на GitHub.

### 4. Керована практика (20–30 хв)
Кожен студент створює власний репозиторій на GitHub і відправляє туди свій `Calculator.java` з усією історією комітів і гілок, накопиченою за заняття 020–030.

### 5. Самостійна практика / челендж (20–30 хв)
Внести невелику зміну в `Calculator.java` НАПРЯМУ на GitHub через веб-інтерфейс (кнопка "Edit" на сторінці файлу, з комітом прямо в браузері), потім виконати `git pull` локально і переконатись, що зміна "прийшла" на комп'ютер. Челендж: створити ще одну теку на комп'ютері й виконати `git clone` свого ж репозиторію туди — переконатись, що весь код і історія комітів скопіювались повністю.

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: чим життя розробника відрізнялося б без GitHub (чи подібного сервісу) — команда не змогла б легко ділитися кодом і синхронізувати роботу кількох людей над одним проєктом.

## Домашнє завдання (необов'язково)
Додати короткий опис проєкту в поле "About" на сторінці репозиторію GitHub (праворуч від списку файлів).
