# Гілки (branches)

**Блок:** Блок 4. Git та інструменти розробника
**Код заняття:** `040-git-instrumenty/030-gilky-branches.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
branch, checkout, merge.

## Мета заняття
- Розуміти, навіщо потрібні гілки (branches)
- Вміти створювати гілку, перемикатись між гілками, зливати (merge) їх
- Розуміти fast-forward merge як найпростіший випадок злиття

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Запитати групу: «Уявіть, що ви експериментуєте з новою функцією в калькуляторі, а вона наполовину зламала все інше. Як повернутись до робочої версії, не втративши напрацьоване?» Гілки — саме про це: можна експериментувати в ізольованому "паралельному всесвіті" коду, не чіпаючи стабільну версію.

### 2. Коротка теорія (15–20 хв)
**Що таке гілка.** Гілка — незалежна лінія розробки. Основна гілка (зазвичай `main`) містить стабільний код; нові функції розробляють в окремих гілках, і зливають назад у `main`, коли готово й перевірено.

**Команди:**
```
git branch назва-гілки     # створити нову гілку (не перемикає на неї)
git checkout назва-гілки   # перемкнутись на гілку
git checkout -b нова-гілка # створити І одразу перемкнутись (скорочення двох команд)
git branch                 # список гілок, поточна позначена зірочкою *
```

**`git merge`.** Зливає зміни з ІНШОЇ гілки в ПОТОЧНУ. Якщо поточна гілка не змінювалась з моменту відгалуження — Git просто "пересуває вказівник" вперед (**fast-forward merge**), без створення окремого коміту злиття. Це найпростіший і найчастіший випадок для невеликих, лінійних змін.

### 3. Демонстрація / live-coding (15–20 хв)
Виконати наживо (реально перевірена послідовність):
```
git branch feature-vitannya
git checkout feature-vitannya
# Switched to branch 'feature-vitannya'

# ... вносимо зміну в Calculator.java, наприклад додаємо привітання ...
git add Calculator.java
git commit -m "Додав привітання на гілці"

git checkout main
# Switched to branch 'main'
# (файл ще БЕЗ змін з гілки - показати це наживо)

git merge feature-vitannya
# Updating 3e0f3a9..661bc67
# Fast-forward
# (тепер зміни з гілки з'явились і в main)
```

### 4. Керована практика (20–30 хв)
Кожен студент створює власну гілку `feature/moje-imya`, вносить у `Calculator.java` невелику власну зміну (наприклад, змінює текст повідомлення про помилку), комітить, перемикається назад на `main`, зливає гілку через `merge`, перевіряє результат.

### 5. Самостійна практика / челендж (20–30 хв)
Створити другу гілку `feature/kvadrat` і додати в `calculate()` нову операцію — обчислення квадрата числа (`"кв"` → `a * a`, ігноруючи `b`). Злити її в `main`. Переглянути повну історію гілок командою `git log --oneline --graph --all`.

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: чому не варто розробляти нову функцію одразу в `main`? (Відповідь: якщо щось піде не так посеред роботи, `main` лишається стабільним і придатним для використання, поки проблему не вирішено в окремій гілці).

## Домашнє завдання (необов'язково)
Створити ще одну гілку з новою операцією на власний вибір (наприклад корінь квадратний — `Math.sqrt(a)`), і злити її в `main`.
