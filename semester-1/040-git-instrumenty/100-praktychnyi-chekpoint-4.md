# Практичний чекпоінт №4

**Блок:** Блок 4. Git та інструменти розробника
**Код заняття:** `040-git-instrumenty/100-praktychnyi-chekpoint-4.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
Індивідуальний проект з блоку 2-3, викладений на GitHub.

## Мета заняття
- Самостійно опублікувати раніше написаний проєкт на GitHub з нуля до готового вигляду
- Застосувати весь інструментарій блоку: git-репозиторій, осмислена історія комітів, `.gitignore`, `README.md`
- Отримати перший елемент реального портфоліо на GitHub

## Структура заняття

### 1. Хук / мотивація (5 хв)
«Сьогодні — не нова тема, а застосування всього блоку 4 до вашого ВЛАСНОГО коду. У вас уже є як мінімум два готові проєкти — міні-гра чи калькулятор з чекпоінту блоку 1, і система з класами (бібліотека/облік студентів) з чекпоінту блоку 2. Сьогодні один із них стане першим справжнім пунктом вашого портфоліо на GitHub».

### 2. Теорія
Відсутня — це повністю практичне заняття.

### 3. Інструктаж (10–15 хв)
**Критерії готового результату:**
- Проєкт має власний репозиторій на GitHub (публічний, якщо студент не проти показувати цей код майбутнім роботодавцям).
- Історія складається З КІЛЬКОХ комітів зі змістовними повідомленнями (не один "initial commit" з усім кодом одразу) — за потреби можна розбити існуючий код на кілька логічних комітів навіть заднім числом.
- Є `.gitignore` (виключає `.idea`, `out`/`target`, скомпільовані `.class`-файли).
- Є `README.md` з описом проєкту, переліком можливостей і короткою інструкцією запуску.
- Немає зайвого сміття в репозиторії (тимчасові файли, скомпільовані класи, якщо вони випадково потрапили в git до додавання `.gitignore`).

**Якщо потрібно "прибрати" файли, які вже потрапили в git до `.gitignore`:**
```
git rm -r --cached .idea
git rm -r --cached out
git commit -m "Прибрав файли IDE зі сховища, додав .gitignore"
```

### 4–5. Практика (60–80 хв)
Кожен студент самостійно обирає ОДИН зі своїх попередніх проєктів (чекпоінт блоку 1 або блоку 2) і проходить повний цикл:
1. Створити локальний git-репозиторій у теці проєкту (`git init`), якщо ще не створено.
2. Додати `.gitignore`.
3. Зробити перший (або кілька) комітів з осмисленими повідомленнями.
4. Створити репозиторій на GitHub і `push` туди.
5. Написати `README.md` і закомітити окремо.

Викладач і ментори ходять між студентами, допомагають із труднощами, особливо якщо в когось лишились непрочищені файли IDE в старій версії проєкту без `.gitignore`.

### 6. Рефлексія / міні-захист (15–20 хв)
Кожен студент за 2–3 хвилини показує групі свій репозиторій на GitHub: назву, README, структуру комітів. Це вже виглядає як справжнє портфоліо — гарний момент відзначити прогрес за весь семестр: від "Hello, World!" до першого проєкту, який реально можна показати.
