# Практика: командний міні-проект

**Блок:** Блок 4. Git та інструменти розробника
**Код заняття:** `040-git-instrumenty/080-komandnyi-mini-proekt.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
Робота в парах/групах через спільний репозиторій.

## Мета заняття
- Застосувати весь git-інструментарій блоку (гілки, remote, PR, конфлікти) в одному завданні
- Попрацювати в парі над спільним репозиторієм, як у реальній команді
- Отримати досвід code review чужого коду й реакції на review власного

## Підготовка викладача (перед заняттям)
- Заздалегідь розбити групу на пари (або дозволити обрати самим).
- Підготувати список 4–6 невеликих можливих "фіч" для калькулятора на вибір (нижче), щоб пари не витрачали час на вигадування завдання.

## Структура заняття

### 1. Хук / мотивація (5 хв)
«Сьогодні — повний цикл командної роботи над одним репозиторієм: гілки, Pull Request, можливо конфлікти — усе, що вивчали окремо за попередні заняття, разом в одному завданні».

### 2. Теорія
Відсутня — це повністю практичне заняття.

### 3. Інструктаж (10–15 хв)
**Формат роботи:**
1. Один студент у парі створює НОВИЙ спільний репозиторій на GitHub (наприклад `calculator-team`) з базовою версією `Calculator.java` (можна взяти свою поточну версію з попередніх занять).
2. Додає партнера як Collaborator (Settings → Collaborators).
3. Партнер клонує репозиторій собі (`git clone`).
4. Обоє обирають РІЗНІ невеликі функції для додавання (список нижче) і працюють у ОКРЕМИХ гілках одночасно.
5. Кожен відкриває Pull Request зі своєю функцією.
6. Партнери переглядають PR одне одного (щонайменше один коментар кожному) і зливають.
7. Якщо виник конфлікт (наприклад, обоє редагували `calculate()` в одному місці) — вирішують його разом, як на занятті 060.

**Можливі функції на вибір (кожна пара обирає РІЗНІ дві, щоб імовірність конфлікту в `calculate()` була реальною, а не гарантованою):**
- Операція піднесення до степеня (`^`) — якщо ще не додано раніше.
- Операція остачі від ділення (`%`) — якщо ще не додано раніше.
- Історія обчислень: зберігати останні 5 результатів в `ArrayList<String>` і виводити за командою.
- Перевірка ділення на нуль з власним повідомленням замість `Infinity`.
- Підтримка кількох послідовних обчислень поспіль без перезапуску програми (цикл навколо всього `main`).
- README з описом усіх підтримуваних операцій.

### 4–5. Практика (60–80 хв)
Пари працюють за форматом вище. Викладач ходить між парами, допомагає з технічними труднощами (найчастіше — саме на етапі підключення Collaborator, першого `push`/`pull` чи вирішення конфлікту), але дає парам самим спробувати розібратись перш ніж підказувати.

### 6. Рефлексія та підсумок (15–20 хв)
Кожна пара коротко (2–3 хв) розповідає групі: що додали, чи був конфлікт і як його вирішили, як пройшов взаємний code review. Обговорити типові труднощі, що виникали в кількох парах одночасно.

## Домашнє завдання (необов'язково)
Додати до спільного репозиторію ще одну функцію на вибір пари, повторивши повний цикл (гілка → PR → review → merge) самостійно.
