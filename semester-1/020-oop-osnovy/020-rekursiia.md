# Рекурсія (recursion)

**Блок:** Блок 2. Методи та основи ООП
**Код заняття:** `020-oop-osnovy/020-rekursiia.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
Базові приклади, коли застосовна.

## Мета заняття
- Розуміти ідею рекурсії: метод, що викликає сам себе
- Вміти виділити базовий випадок (base case) і рекурсивний випадок
- Розуміти на прикладі, чому рекурсія без базового випадку "зависає"

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Аналогія на дошці: рекурсія — як дві дзеркала, поставлені одне навпроти одного: зображення повторюється всередині себе, зменшуючись. Або: «Уявіть, що я прошу вас порахувати кількість людей у черзі, стоячи в її кінці, запитавши лише в людини перед вами: "скільки людей перед тобою?", а та людина запитує те саме в наступної — і так до самого початку черги». Запустити [`Factorial.java`](src/020-rekursiia/Factorial.java) наживо.

### 2. Коротка теорія (15–20 хв)
**Що таке рекурсія.** Рекурсивний метод — це метод, який викликає сам себе. Кожен такий метод має складатись із двох обов'язкових частин:
- **Базовий випадок (base case)** — умова, коли рекурсія ЗУПИНЯЄТЬСЯ і повертає готовий результат без подальших викликів.
- **Рекурсивний випадок** — метод викликає сам себе з "меншою" чи "простішою" версією задачі, наближаючи її до базового випадку.

```java
static int factorial(int n) {
    if (n <= 1) {
        return 1;               // базовий випадок
    }
    return n * factorial(n - 1); // рекурсивний випадок
}
```

**Що станеться без базового випадку.** Метод викликатиме сам себе нескінченно, поки програма не впаде з помилкою `StackOverflowError` — пам'ять, відведена під "стек викликів", вичерпається. Варто показати це наживо (тимчасово прибрати умову базового випадку) — переконатись, що ефект справді видно, дуже наочно пояснює важливість базового випадку.

**Коли застосовна рекурсія.** Зручна там, де задача природно розбивається на таку саму, але меншу задачу: обчислення факторіала, обхід деревовидних структур (дерева файлів/папок, майбутні теми з структур даних), числа Фібоначчі. Для простих задач на кшталт суми чисел від 1 до N — обидва підходи (цикл і рекурсія) працюють однаково добре; рекурсія тут для демонстрації підходу, а не тому, що цикл гірший.

### 3. Демонстрація / live-coding (15–20 хв)
Розібрати [`Factorial.java`](src/020-rekursiia/Factorial.java) рядок за рядком, і — найважливіше — розписати на дошці "розкрутку" викликів для `factorial(5)`, показуючи, як виклики накопичуються, а потім результати повертаються назад знизу вгору (коментар у файлі містить готовий приклад такого розпису).

### 4. Керована практика (20–30 хв)
Разом написати [`RecursiveSum.java`](src/020-rekursiia/RecursiveSum.java) — сума чисел від 1 до N рекурсивно. Порівняти з ітеративним варіантом `SumToN.java` із блоку 1 — той самий результат, інший підхід.

### 5. Самостійна практика / челендж (20–30 хв)
Написати [`Fibonacci.java`](src/020-rekursiia/Fibonacci.java) — n-те число Фібоначчі рекурсивно (0, 1, 1, 2, 3, 5, 8, 13...). Челендж для найшвидших: спробувати запустити `fibonacci(40)` і подивитись, скільки часу це займе — гарна нагода обговорити, що рекурсія не завжди ефективна (тут вона викликає сама себе двічі на кожному кроці).

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: коли рекурсія зручніша за цикл, а коли навпаки. Чесно визнати: на цьому занятті важливіше зрозуміти саму ідею "виклику самого себе", ніж одразу вільно писати будь-яку рекурсію — це прийде з практикою.

## Домашнє завдання (необов'язково)
Написати рекурсивний метод, що рахує суму цифр числа (наприклад, для 12345 — 1+2+3+4+5 = 15).
