# Вступ до ООП. Класи та об'єкти

**Блок:** Блок 2. Методи та основи ООП
**Код заняття:** `020-oop-osnovy/040-vstup-oop-klasy-obiekty.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
Що таке клас, об'єкт, поля, ідея ООП.

## Мета заняття
- Розуміти ідею ООП: об'єднання даних (полів) і сенсу (поведінки) в одну сутність
- Розуміти різницю між класом (кресленням) і об'єктом (конкретним екземпляром)
- Вміти оголосити простий клас з полями і створити кілька об'єктів цього класу

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Аналогія на дошці: **клас — це креслення будинку, об'єкт — конкретний будинок, збудований за цим кресленням.** За одним кресленням можна збудувати скільки завгодно будинків, і кожен з них — окремий, зі своєю адресою, кольором стін тощо, хоча всі побудовані за тим самим планом. Запустити [`DogDemo.java`](src/040-vstup-oop-klasy-obiekty/DogDemo.java) — два об'єкти класу `Dog` з різними значеннями полів.

### 2. Коротка теорія (15–20 хв)
**Чому взагалі ООП.** Досі студенти зберігали пов'язані дані в окремих змінних або паралельних масивах (наприклад, масив імен студентів і окремий масив їхніх оцінок). Проблема: ніщо в коді не показує явно, що `names[i]` і `grades[i]` стосуються ОДНІЄЇ людини. ООП (об'єктно-орієнтоване програмування) вирішує це, об'єднуючи пов'язані дані в одну сутність — об'єкт.

**Клас** — це "креслення" чи "шаблон", що описує, які поля (дані) і методи (поведінка) матиме кожен об'єкт цього типу:
```java
public class Dog {
    String name;
    String breed;
    int age;
}
```
Тут `Dog` поки що не має методів, тільки поля — і це нормально для першого кроку.

**Об'єкт** — конкретний екземпляр класу, створений через ключове слово `new`:
```java
Dog firstDog = new Dog();
firstDog.name = "Рекс";
firstDog.age = 3;
```
`new Dog()` виділяє пам'ять під новий, окремий об'єкт. Звернення до поля конкретного об'єкта — через крапку: `firstDog.name`.

**Два файли — це нормально.** Починаючи з цього заняття, приклади частіше складаються з двох файлів: клас-модель (наприклад `Dog.java`, без `main()`) і окремий клас, який його використовує (`DogDemo.java`, з `main()`). Це звичайна практика в реальних Java-проєктах, а не помилка.

### 3. Демонстрація / live-coding (15–20 хв)
Розібрати пару [`Dog.java`](src/040-vstup-oop-klasy-obiekty/Dog.java) + [`DogDemo.java`](src/040-vstup-oop-klasy-obiekty/DogDemo.java): створення двох незалежних об'єктів `Dog`, заповнення їхніх полів, вивід. Наголосити: зміна поля `firstDog.age` жодним чином не впливає на `secondDog` — це справді два окремі об'єкти.

### 4. Керована практика (20–30 хв)
Разом написати пару [`Book.java`](src/040-vstup-oop-klasy-obiekty/Book.java) + [`BookDemo.java`](src/040-vstup-oop-klasy-obiekty/BookDemo.java) — той самий принцип, новий приклад: клас книги з полями `title`, `author`, `pages`.

### 5. Самостійна практика / челендж (20–30 хв)
Розібрати [`Student.java`](src/040-vstup-oop-klasy-obiekty/Student.java) + [`StudentDemo.java`](src/040-vstup-oop-klasy-obiekty/StudentDemo.java) — челендж, що об'єднує класи з масивами з попереднього заняття: масив об'єктів `Student`, підрахунок середнього балу групи і виведення імен студентів з балом вище середнього.

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: «Чому масив `Student[]` зручніший за два паралельні масиви `String[] names` і `int[] grades`?» Закріпити основну ідею заняття перед тим, як на наступних заняттях додавати класам методи і "розумнішу" поведінку.

## Домашнє завдання (необов'язково)
Створити власний клас (наприклад `Movie` з полями `title`, `genre`, `rating`) і масив із 3–5 об'єктів цього класу; вивести назви фільмів з рейтингом вище заданого порогу.
