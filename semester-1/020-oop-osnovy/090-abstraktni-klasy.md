# Абстрактні класи

**Блок:** Блок 2. Методи та основи ООП
**Код заняття:** `020-oop-osnovy/090-abstraktni-klasy.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
abstract class, коли інтерфейс, а коли абстрактний клас.

## Мета заняття
- Розуміти, що таке абстрактний клас і чим він відрізняється від інтерфейсу
- Вміти оголошувати абстрактний метод і звичайний (з готовою реалізацією) в одному абстрактному класі
- Мати практичне правило вибору між інтерфейсом і абстрактним класом

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Нагадати минуле заняття — інтерфейс `Shape` з методом `area()`, реалізований у `Circle` і `RectangleShape`. Запитати: «А якщо ми хочемо, щоб КОЖНА фігура мала ще й метод `printInfo()`, який виглядає ОДНАКОВО для всіх фігур (просто виводить назву й площу) — чи доведеться писати цей метод в кожному класі окремо?» Запустити [`AbstractShapeDemo.java`](src/090-abstraktni-klasy/AbstractShapeDemo.java) — показати, що `printInfo()` написаний лише один раз, а працює для обох фігур.

### 2. Коротка теорія (15–20 хв)
**Головна відмінність від інтерфейсу.** Інтерфейс (заняття 080) — це чистий "контракт" без жодної реалізації. Абстрактний клас може мати ОБИДВА типи методів одночасно:
- **Абстрактний метод** (`abstract`, без тіла) — кожен нащадок ЗОБОВ'ЯЗАНИЙ його реалізувати, так само як і в інтерфейсі.
- **Звичайний метод** (із готовою реалізацією) — успадковується нащадками "як є", без потреби переписувати.

```java
public abstract class AbstractShape {
    String name;
    AbstractShape(String name) { this.name = name; }

    abstract double area(); // немає тіла - обов'язково реалізувати в нащадку

    void printInfo() { // готова реалізація - успадковується "безкоштовно"
        System.out.println(name + ": площа = " + area());
    }
}
```

**Не можна створити об'єкт абстрактного класу напряму.** `new AbstractShape("...")` не скомпілюється — абстрактний клас існує лише для того, щоб від нього успадковувались конкретні класи (`CircleAbstract`, `SquareAbstract`), які реалізують усі абстрактні методи.

**Практичне правило вибору.**
- Якщо класи не мають ЖОДНОЇ спільної реалізації, лише спільний "контракт" (набір методів, які мають бути) — **інтерфейс**.
- Якщо є хоча б трохи спільного коду, який хочеться написати один раз і успадкувати — **абстрактний клас**.
- Реальні великі Java-проєкти часто поєднують обидва підходи одночасно — це нормально, вони не взаємовиключні.

### 3. Демонстрація / live-coding (15–20 хв)
Розібрати [`AbstractShape.java`](src/090-abstraktni-klasy/AbstractShape.java), [`CircleAbstract.java`](src/090-abstraktni-klasy/CircleAbstract.java), [`SquareAbstract.java`](src/090-abstraktni-klasy/SquareAbstract.java) і [`AbstractShapeDemo.java`](src/090-abstraktni-klasy/AbstractShapeDemo.java) — поставити поруч з учорашнім інтерфейсним варіантом `Shape` і візуально порівняти обидва підходи до тієї самої задачі.

### 4. Керована практика (20–30 хв)
Обговорити й переписати разом метод `printInfo()`, додавши ще одну деталь у вивід (наприклад, округлення площі до двох знаків після коми через `String.format` чи `printf`, як на занятті про умови в блоці 1) — показати, що зміна в ОДНОМУ місці (`AbstractShape`) одразу стосується обох нащадків без жодної правки в `CircleAbstract`/`SquareAbstract`.

### 5. Самостійна практика / челендж (20–30 хв)
Додати ще одного нащадка — прямокутник — до ієрархії `AbstractShape`, реалізувавши `area()`. [`RectangleAbstract.java`](src/090-abstraktni-klasy/RectangleAbstract.java) — приклад розв'язку для звірки після самостійної спроби.

### 6. Рефлексія та підсумок (5–10 хв)
Підсумувати весь блок класично-важливих тем ООП, розглянутих у заняттях 040–090: клас/об'єкт → конструктор → інкапсуляція → наслідування → поліморфізм (інтерфейси) → абстрактні класи. Запитати групу, яка тема здалась найскладнішою — приділити їй кілька додаткових хвилин перед чекпоінтом.
