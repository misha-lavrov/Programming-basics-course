# Що таке бази даних

**Блок:** Блок 5. Основи баз даних
**Код заняття:** `050-bazy-danyh/010-shcho-take-bazy-danyh.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
Навіщо потрібні, огляд реляційних/нереляційних (SQL vs NoSQL).

## Мета заняття
- Розуміти, навіщо потрібна база даних, а не просто файли/масиви в програмі
- Знати різницю між реляційними (SQL) і нереляційними (NoSQL) базами даних на загальному рівні
- Мати загальне уявлення, куди веде цей блок (SQL-запити → JDBC з Java)

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Нагадати заняття 090 з блоку 3 (робота з файлами): дані там зберігались у звичайному текстовому файлі. Запитати: «А що, якщо потрібно зберігати мільйони записів, швидко знаходити конкретні серед них, і щоб кілька програм могли безпечно працювати з тими самими даними одночасно?» Звичайний файл із цим не впорається — для цього і існують бази даних.

### 2. Коротка теорія (15–20 хв)
**Що таке база даних.** Організоване сховище даних, спроєктоване для швидкого й надійного зберігання, пошуку та зміни інформації — на відміну від файлу, база даних гарантує коректність даних навіть при одночасному доступі багатьох користувачів чи програм.

**СУБД (система управління базами даних).** Програмне забезпечення, що керує базою даних: приймає запити, виконує їх, гарантує цілісність даних. Приклади: PostgreSQL, MySQL, SQLite, MongoDB. "База даних" — самі дані; "СУБД" — програма, що ними керує (на практиці ці терміни часто вживають як синоніми в розмові).

**Реляційні бази даних (SQL).** Дані організовані у ВЗАЄМОПОВ'ЯЗАНІ таблиці (звідси "реляційні" — від "relation", зв'язок): кожна таблиця має чітко визначені стовпці (типи даних наперед відомі), а зв'язки між таблицями підтримуються явно. Запити пишуться мовою SQL (Structured Query Language). Приклади: PostgreSQL, MySQL, SQLite, Oracle. Саме цей тип розглядатимемо в цьому блоці.

**Нереляційні бази даних (NoSQL).** Загальна назва для баз даних, що НЕ використовують реляційну модель — структура даних гнучкіша (документи, пари ключ-значення, графи тощо), часто ціною суворих гарантій цілісності. Приклади: MongoDB (документо-орієнтована), Redis (ключ-значення). Не мають єдиної "SQL-подібної" мови запитів — кожна NoSQL-система має свою.

**Коли який тип обирають на практиці.** Реляційні бази — стандартний вибір для даних із чіткою структурою й важливими зв'язками (фінанси, облік, більшість бізнес-застосунків). NoSQL — коли структура даних дуже гнучка або мінлива, чи коли потрібна екстремальна швидкість запису великих обсягів даних без суворих зв'язків. Для старту й переважної більшості вакансій junior-розробника — реляційні бази й SQL є базовою, обов'язковою навичкою.

### 3. Демонстрація / live-coding (15–20 хв)
Без коду поки що — замість цього намалювати на дошці просту таблицю "студенти" (стовпці: ім'я, рік народження, група) з 3–4 рядками даних. Показати, як природно дані студентів лягають у рядки й стовпці — підготовка інтуїції до реляційної моделі, яку детально розберемо наступного заняття.

### 4. Керована практика (20–30 хв)
Разом з групою спроєктувати (на дошці, без коду) просту структуру таблиць для домашньої бібліотеки: які стовпці потрібні для запису "книга"? А для запису "автор"? Чи варто зберігати ім'я автора в кожному записі книги, чи окремо? — підвести до ідеї зв'язків між таблицями, яку розгорнемо в заняттях 020 і 080.

### 5. Самостійна практика / челендж (20–30 хв)
Кожен студент самостійно накидає (на папері чи в нотатках) структуру таблиць для власної ідеї — наприклад, колекція фільмів, список улюблених ігор з оцінками, облік кишенькових витрат. Достатньо просто перелічити, які "таблиці" потрібні і які стовпці в кожній.

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити кілька студентських ідей вголос. Анонсувати план блоку: реляційна модель → встановлення PostgreSQL → SQL (SELECT, зміна даних, JOIN, агрегація) → проектування бази → підключення з Java (JDBC) → чекпоінт.

## Домашнє завдання (необов'язково)
Знайти й коротко переглянути (5–10 хв) будь-яку публічну базу даних чи таблицю в інтернеті (наприклад, експорт даних у форматі CSV/таблиці) — звернути увагу на стовпці й типи даних у них.
