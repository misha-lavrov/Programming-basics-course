# SQL: вибірка даних

**Блок:** Блок 5. Основи баз даних
**Код заняття:** `050-bazy-danyh/040-sql-select.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
SELECT, WHERE, ORDER BY.

## Мета заняття
- Вміти вибрати всі або конкретні стовпці таблиці через `SELECT`
- Вміти фільтрувати рядки через `WHERE`
- Вміти сортувати результат через `ORDER BY`

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Відкрити в DBeaver базу `college_db` (із заняття 030), виконати `SELECT * FROM students;` наживо — показати результат у зручній табличній формі. Сказати: «Один рядок коду — і ви бачите всі дані. Сьогодні навчимось запитувати саме те, що потрібно, а не все підряд».

### 2. Коротка теорія (15–20 хв)
**`SELECT` — вибір даних:**
```sql
SELECT * FROM students;                  -- усі стовпці
SELECT name, birth_year FROM students;   -- лише потрібні стовпці
```

**`WHERE` — фільтрація рядків за умовою** (ті самі оператори порівняння `= != > < >= <=` і логічні `AND OR NOT`, знайомі з Java, блок 1):
```sql
SELECT name FROM students WHERE birth_year = 2006;
SELECT name FROM students WHERE birth_year = 2006 AND group_id = 1;
```

**`ORDER BY` — сортування результату:**
```sql
SELECT name, birth_year FROM students ORDER BY birth_year;      -- за зростанням (за замовчуванням)
SELECT name, birth_year FROM students ORDER BY birth_year DESC; -- за спаданням
```

**`LIKE` — пошук за частковим збігом тексту** (`%` замінює будь-яку кількість будь-яких символів):
```sql
SELECT name FROM students WHERE name LIKE 'О%'; -- імена, що починаються на "О"
```

**Порядок виконання запиту (для розуміння, не для запам'ятовування напам'ять):** SQL спочатку "уявно" визначає, З ЯКОЇ таблиці брати дані (`FROM`), потім ФІЛЬТРУЄ рядки (`WHERE`), і лише тоді обирає, ЯКІ стовпці показати (`SELECT`) і в якому порядку (`ORDER BY`) — хоча в самому тексті запиту `SELECT` пишеться першим.

### 3. Демонстрація / live-coding (15–20 хв)
Виконати наживо в DBeaver кожен запит із [`queries.sql`](src/040-sql-select/queries.sql) по черзі, обговорюючи результат кожного — усі запити перевірені заздалегідь і дають передбачувані результати на нашій спільній базі даних.

### 4. Керована практика (20–30 хв)
Разом написати кілька нових запитів "з нуля" за словесним описом (не дивлячись у готовий файл): «Знайти імена всіх студентів групи з `id=2`», «Вивести всі оцінки, менші за 75, від найменшої до найбільшої».

### 5. Самостійна практика / челендж (20–30 хв)
Самостійно написати запити:
- Усі студенти, народжені до 2006 року, відсортовані за іменем.
- Усі оцінки з предмета з `id=1` (Java), від найвищої до найнижчої.
- Челендж: студенти, чиє ім'я містить букву "а" (використовуючи `LIKE '%а%'`).

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: чому `WHERE` — це вже частина роботи з реальними даними (у справжніх базах — мільйони рядків, і `SELECT *` без `WHERE` там просто непрактичний).

## Домашнє завдання (необов'язково)
Написати 3 власні запити до бази `college_db`, використовуючи комбінацію `WHERE` і `ORDER BY`.
