# Реляційна модель

**Блок:** Блок 5. Основи баз даних
**Код заняття:** `050-bazy-danyh/020-reliatsiina-model.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
Таблиці, рядки, стовпці, ключі (primary/foreign key).

## Мета заняття
- Знати базові терміни реляційної моделі: таблиця, рядок, стовпець
- Розуміти призначення первинного ключа (primary key) і зовнішнього ключа (foreign key)
- Познайомитись зі спільною навчальною базою даних, яку використовуватимемо до кінця блоку

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Показати на дошці таблицю студентів із заняття 010 і запитати: «Як точно вказати на КОНКРЕТНОГО студента, якщо в групі можуть бути двоє з однаковим іменем?» Підвести до ідеї унікального ідентифікатора — первинного ключа.

### 2. Коротка теорія (15–20 хв)
**Таблиця, рядок, стовпець.** Таблиця (table) — набір однотипних записів (наприклад, усі студенти). Рядок (row) — один конкретний запис (один студент). Стовпець (column) — конкретна властивість кожного запису (ім'я, рік народження) з наперед визначеним типом даних.

**Первинний ключ (primary key).** Стовпець (чи набір стовпців), що ОДНОЗНАЧНО ідентифікує кожен рядок таблиці — жодні два рядки не можуть мати однакове значення первинного ключа. Найчастіше — просте число, що автоматично збільшується для кожного нового запису (`id`).

**Зовнішній ключ (foreign key).** Стовпець в одній таблиці, що посилається на первинний ключ ІНШОЇ таблиці — саме так реляційна модель виражає зв'язки між таблицями. Наприклад, стовпець `group_id` у таблиці `students` посилається на `id` у таблиці `groups`: це означає «цей студент належить до цієї групи».

**Наша спільна навчальна база даних (буде використовуватись до кінця блоку):**
```sql
CREATE TABLE groups (
    id SERIAL PRIMARY KEY,
    name VARCHAR(20) NOT NULL
);

CREATE TABLE students (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    birth_year INT,
    group_id INT REFERENCES groups(id)
);
```
`SERIAL` — спеціальний тип PostgreSQL для автоматично зростаючого цілого числа (звичний "id, що сам рахується"). `REFERENCES groups(id)` — оголошує зовнішній ключ явно: PostgreSQL сам стежитиме, щоб `group_id` завжди вказував на реально існуючу групу.

**Типи даних стовпців (базовий набір):** `INT` (ціле число), `VARCHAR(n)` (текст обмеженої довжини), `DATE` (дата), `BOOLEAN` (так/ні) — прямі аналоги типів Java (`int`, `String`, `boolean`), які вже добре знайомі.

### 3. Демонстрація / live-coding (15–20 хв)
Розібрати повну схему бази даних із [`schema.sql`](src/020-reliatsiina-model/schema.sql) — усі чотири таблиці (`groups`, `students`, `subjects`, `grades`), пояснюючи кожен зовнішній ключ: `students.group_id → groups.id`, `grades.student_id → students.id`, `grades.subject_id → subjects.id`. Намалювати на дошці схему зв'язків (простий ER-подібний малюнок: прямокутники-таблиці, стрілки-зв'язки).

### 4. Керована практика (20–30 хв)
Разом виконати [`seed-data.sql`](src/020-reliatsiina-model/seed-data.sql) (після `schema.sql`) — наповнити таблиці тестовими даними. Обговорити конкретні рядки: «Що означає рядок `(1, 1, 92, '2026-03-01')` у таблиці `grades`?» — прочитати його як речення завдяки зовнішнім ключам («студент з id=1 отримав 92 бали з предмета з id=1»).

### 5. Самостійна практика / челендж (20–30 хв)
Кожен студент домальовує на своєму малюнку зв'язків ще одну гіпотетичну таблицю — наприклад `teachers` (викладачі) із зв'язком до `subjects` (який викладач веде який предмет) — не обов'язково писати SQL, досить намалювати й пояснити зв'язок словами.

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: чому дані розбиті на 4 окремі таблиці, а не в одну велику — коротко анонсувати, що це питання детально розберемо на занятті 080 (нормалізація), а поки досить інтуїтивного розуміння.
