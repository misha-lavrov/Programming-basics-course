# SQL: агрегація

**Блок:** Блок 5. Основи баз даних
**Код заняття:** `050-bazy-danyh/070-sql-agregatsiia.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
COUNT, SUM, AVG, GROUP BY.

## Мета заняття
- Вміти використовувати агрегатні функції `COUNT`, `SUM`, `AVG`
- Вміти групувати рядки через `GROUP BY` і рахувати агрегат ОКРЕМО для кожної групи
- Вміти фільтрувати результат групування через `HAVING`

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Запитати: «Як порахувати середній бал КОЖНОГО студента одним запитом, а не вручну діставати оцінки кожного окремо?» Виконати наживо `SELECT AVG(grade) FROM grades;` — показати загальне середнє, а потім поставити питання: «А як зробити те саме, але ОКРЕМО для кожного студента?» — підвести до `GROUP BY`.

### 2. Коротка теорія (15–20 хв)
**Агрегатні функції — рахують ОДНЕ значення з багатьох рядків:**
```sql
SELECT COUNT(*) FROM students;        -- кількість рядків
SELECT SUM(grade) FROM grades;        -- сума значень
SELECT AVG(grade) FROM grades;        -- середнє значення
```

**`GROUP BY` — розбити рядки на групи за значенням стовпця і порахувати агрегат ОКРЕМО для кожної групи:**
```sql
SELECT s.name, AVG(gr.grade) AS average_grade
FROM grades gr
INNER JOIN students s ON gr.student_id = s.id
GROUP BY s.name;
```
Це читається так: «розбий усі оцінки на групи за іменем студента, і для кожної групи порахуй середнє значення `grade`».

**Правило синтаксису `GROUP BY`:** у `SELECT` можна вказувати ЛИШЕ ті стовпці, за якими групуємо (`s.name`), і результати агрегатних функцій (`AVG(gr.grade)`) — не можна одночасно вивести якийсь довільний стовпець із групи, бо для групи з кількох рядків незрозуміло, який саме з них показати.

**`HAVING` — фільтрація ПІСЛЯ групування** (на відміну від `WHERE`, який фільтрує рядки ДО групування й не може перевіряти результат агрегатної функції):
```sql
SELECT s.name, AVG(gr.grade) AS average_grade
FROM grades gr
INNER JOIN students s ON gr.student_id = s.id
GROUP BY s.name
HAVING AVG(gr.grade) >= 85;
```

### 3. Демонстрація / live-coding (15–20 хв)
Виконати наживо всі запити з [`queries.sql`](src/070-sql-agregatsiia/queries.sql): загальний `COUNT`/`SUM`/`AVG`, `GROUP BY` за студентом, `GROUP BY` за предметом (із `COUNT` кількості оцінок на додачу), і `HAVING`.

### 4. Керована практика (20–30 хв)
Разом написати запит: скільки студентів у КОЖНІЙ групі (`GROUP BY group_id`, `COUNT(*)`, з `JOIN` до `groups` для назви).

### 5. Самостійна практика / челендж (20–30 хв)
Самостійно написати запити:
- Середній бал КОЖНОГО предмета, відсортований від найвищого до найнижчого.
- Скільки оцінок отримав КОЖЕН студент (`COUNT`, а не `AVG`).
- Челендж: студенти, у яких МЕНШЕ ніж 2 оцінки (підказка: `GROUP BY` + `HAVING COUNT(*) < 2`).

### 6. Рефлексія та підсумок (5–10 хв)
Підсумувати всю "граматику" SQL, вивчену в блоці: `SELECT` → `FROM` → `JOIN` → `WHERE` → `GROUP BY` → `HAVING` → `ORDER BY` — саме в такому порядку зазвичай і пишуть повний запит, навіть якщо `SELECT` стоїть першим у тексті.

## Домашнє завдання (необов'язково)
Написати запит, що знаходить групу з НАЙВИЩИМ середнім балом серед усіх оцінок її студентів (потрібен `JOIN` трьох таблиць: `grades`, `students`, `groups`, плюс `GROUP BY` і `ORDER BY`).
