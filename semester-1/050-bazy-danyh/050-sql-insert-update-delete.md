# SQL: зміна даних

**Блок:** Блок 5. Основи баз даних
**Код заняття:** `050-bazy-danyh/050-sql-insert-update-delete.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
INSERT, UPDATE, DELETE.

## Мета заняття
- Вміти додавати нові рядки через `INSERT`
- Вміти змінювати існуючі рядки через `UPDATE`
- Вміти видаляти рядки через `DELETE`, розуміючи ризики без `WHERE`

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Запитати: «Минулого заняття ми лише ЧИТАЛИ дані. А що, якщо новий студент прийшов у групу — як додати його в базу?» Показати наживо `INSERT` одного нового рядка в `students` і одразу `SELECT`, що підтверджує — рядок з'явився.

### 2. Коротка теорія (15–20 хв)
**`INSERT` — додавання нового рядка:**
```sql
INSERT INTO students (name, birth_year, group_id) VALUES ('Тарас Гончар', 2006, 2);
```
Стовпець `id` не вказуємо — `SERIAL` (заняття 020) генерує його автоматично.

**`UPDATE` — зміна існуючих рядків:**
```sql
UPDATE students SET group_id = 1 WHERE name = 'Тарас Гончар';
```
**КРИТИЧНО ВАЖЛИВО:** `UPDATE` без `WHERE` змінить **КОЖЕН** рядок таблиці:
```sql
UPDATE students SET group_id = 1; -- НЕБЕЗПЕЧНО: усі студенти опиняться в групі 1!
```
Хороша звичка — спочатку виконати `SELECT` з тим самим `WHERE`, переконатись, що умова відбирає саме потрібні рядки, і лише тоді міняти `SELECT ...` на `UPDATE ... SET ...` в тому самому запиті.

**`DELETE` — видалення рядків:**
```sql
DELETE FROM students WHERE name = 'Тарас Гончар';
```
Той самий ризик, що й з `UPDATE`: `DELETE FROM students;` без `WHERE` видалить **УСІХ** студентів. На реальній роботі випадкове видалення даних без `WHERE` — одна з найпоширеніших і найдорожчих помилок нових розробників.

### 3. Демонстрація / live-coding (15–20 хв)
Виконати наживо повний цикл із [`queries.sql`](src/050-sql-insert-update-delete/queries.sql): додати студента, оновити одне поле, оновити кілька полів одразу, видалити студента — з перевіркою через `SELECT` після кожного кроку.

### 4. Керована практика (20–30 хв)
Разом додати нового студента, кілька оцінок для нього (`INSERT INTO grades ...`), потім виправити одну з оцінок (`UPDATE`), і насамкінець видалити тестові дані (`DELETE`), щоб база лишилась чистою для наступних занять.

### 5. Самостійна практика / челендж (20–30 хв)
Кожен студент самостійно: додає нову групу, додає в неї 2 нових студенти, додає їм по одній оцінці, потім виправляє рік народження одному з них. Челендж: спробувати виконати `UPDATE ... SET grade = 100;` (без `WHERE`) на ТЕСТОВІЙ копії таблиці (`CREATE TABLE grades_test AS SELECT * FROM grades;`) — і на власні очі побачити наслідки, у безпечному "пісочному" середовищі, а не на реальних даних.

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: чому в реальних командах на серйозних проєктах `UPDATE`/`DELETE` без `WHERE` на робочій (production) базі даних — практично завжди помилка, і чому досвідчені розробники завжди двічі перевіряють `WHERE` перед виконанням таких запитів.
