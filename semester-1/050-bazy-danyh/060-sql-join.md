# SQL: об'єднання таблиць

**Блок:** Блок 5. Основи баз даних
**Код заняття:** `050-bazy-danyh/060-sql-join.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
JOIN (INNER/LEFT).

## Мета заняття
- Розуміти, навіщо потрібен `JOIN`, коли дані розбиті на кілька таблиць
- Вміти писати `INNER JOIN` для двох і більше таблиць
- Вміти писати `LEFT JOIN` і розуміти різницю з `INNER JOIN`

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Запитати: «У таблиці `students` є `group_id` — просто число (1, 2...). А як дізнатись НАЗВУ групи, а не її id?» Виконати наживо `SELECT * FROM groups;` і `SELECT * FROM students;` окремо — показати, що дані "розкидані" по двох таблицях. `JOIN` — спосіб об'єднати їх в один результат.

### 2. Коротка теорія (15–20 хв)
**`INNER JOIN` — об'єднання за спільним полем:**
```sql
SELECT s.name, g.name AS group_name
FROM students s
INNER JOIN groups g ON s.group_id = g.id;
```
`ON s.group_id = g.id` — умова об'єднання: "з'єднати рядок студента з рядком групи, де `group_id` студента збігається з `id` групи". `s` і `g` — псевдоніми (aliases) таблиць, щоб не писати повні імена `students`/`groups` щоразу. `AS group_name` — перейменування стовпця результату (обидві таблиці мають стовпець `name`, тому варто розрізняти їх у виводі).

**`INNER JOIN` показує ЛИШЕ рядки, де знайшлась відповідність в ОБОХ таблицях.** Якщо студент має `group_id`, якого не існує в `groups` — такий студент НЕ з'явиться в результаті `INNER JOIN`.

**`LEFT JOIN` — зберігає ВСІ рядки лівої таблиці:**
```sql
SELECT s.name, gr.grade
FROM students s
LEFT JOIN grades gr ON s.id = gr.student_id;
```
Навіть якщо у студента ще НЕМАЄ жодної оцінки — його рядок все одно з'явиться, просто зі значенням `NULL` замість оцінки. `INNER JOIN` у цьому випадку "загубив" би такого студента повністю.

**JOIN кількох таблиць одразу.** Можна поєднати більше двох таблиць в одному запиті, додаючи ще один `JOIN`:
```sql
SELECT s.name AS student_name, sub.name AS subject_name, gr.grade
FROM grades gr
INNER JOIN students s ON gr.student_id = s.id
INNER JOIN subjects sub ON gr.subject_id = sub.id;
```

### 3. Демонстрація / live-coding (15–20 хв)
Виконати наживо всі запити з [`queries.sql`](src/060-sql-join/queries.sql), включно з JOIN трьох таблиць одразу. Особливо звернути увагу на `LEFT JOIN` — у нашій базі є студент Дмитро Савченко, у якого ще НЕМАЄ жодної оцінки; показати, як `INNER JOIN` "губить" його рядок повністю, а `LEFT JOIN` — зберігає з `NULL`.

### 4. Керована практика (20–30 хв)
Разом написати запит: список усіх студентів з назвою ЇХНЬОЇ групи ТА середнім предметом, який вони вивчали (поки без агрегації — просто список усіх пар студент-предмет, агрегацію розберемо наступного заняття).

### 5. Самостійна практика / челендж (20–30 хв)
Самостійно написати запит, що виводить: ім'я студента, назву групи, назву предмета й оцінку — усе в ОДНОМУ рядку результату (JOIN чотирьох таблиць одразу: `students`, `groups`, `subjects`, `grades`). Челендж: додати `WHERE`, щоб показати лише оцінки вищі за 85.

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: чому `LEFT JOIN` іноді критично важливий у реальних задачах — наприклад, звіт "усі клієнти" не повинен губити клієнтів, які ще нічого не замовили, лише тому що в них немає записів у таблиці замовлень.

## Домашнє завдання (необов'язково)
Написати запит, що виводить студентів БЕЗ жодної оцінки (підказка: `LEFT JOIN` + `WHERE grade IS NULL`).
