## Опис
Демо-день, зворотний зв'язок, анонс планів на семестр 2 (фреймворки).

## Мета заняття
- Презентувати завершений фінальний проєкт групі
- Отримати конструктивний зворотний зв'язок від викладача й одногрупників
- Підбити підсумки всього семестру й дізнатись про плани семестру 2

## Структура заняття

### 1. Хук / мотивація (5 хв)
«60 занять тому більшість із вас не написали жодного рядка коду. Сьогодні — демо-день: кожен покаже проєкт, що поєднує Java, бази даних, Git і навіть трохи вебу. Це справжній привід пишатися пройденим шляхом».

### 2. Теорія
Відсутня.

### 3. Формат демо-дня (5 хв інструктажу)
Кожен студент (чи пара) має **5–7 хвилин**: 2–3 хвилини демонстрації проєкту наживо (запуск, кілька операцій меню наочно) + 2–3 хвилини питань і зворотного зв'язку від групи й викладача. Регламент варто дотримуватись чітко, щоб усі встигли виступити.

**Що варто показати кожному:**
- Коротко: яку тему обрали і чому.
- Демонстрація роботи застосунку (хоча б по одному прикладу кожної CRUD-операції).
- Репозиторій на GitHub: README, історія комітів.
- Одна деталь, якою особливо задоволені (архітектурне рішення, вирішена складна помилка, бонусний функціонал).

### 4. Демо-день (основна частина заняття, 60–90 хв залежно від кількості студентів)
Виступи по черзі за форматом вище. Викладач і одногрупники ставлять питання, відзначають сильні сторони кожного проєкту й дають конструктивні поради (за принципом code review з блоку 4 — конструктивно, по суті, без надмірної критики).

### 5. Груповий зворотний зв'язок (10–15 хв)
Коротке обговорення: що виявилось найскладнішим за весь семестр? Яка тема відчувається найупевненіше? Що хотілося б повторити чи заглибити на початку семестру 2?

### 6. Підсумки семестру й анонс семестру 2 (10–15 хв)
**Підсумувати пройдений шлях:** Java-основи → ООП → алгоритми/структури даних → Git → SQL/бази даних → веб-основи → фінальний проєкт. Нагадати заняття 1 ("вступ у професію") — наскільки далі просунулись за ці 60 занять.

**Анонсувати семестр 2 (орієнтовно, без деталей — вони ще не сплановані):** бекенд-фреймворк (ймовірно Spring Boot) для побудови реальних REST API замість ручного `com.sun.net.httpserver`; основи фронтенду; фінальний проєкт семестру — уже повноцінний застосунок із веб-інтерфейсом.
