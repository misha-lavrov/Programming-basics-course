# Тестування API вручну

**Блок:** Блок 6. Основи вебу та фінальний проєкт семестру
**Код заняття:** `060-veb-http-final-proekt/040-postman.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
Робота з Postman.

## Мета заняття
- Встановити Postman
- Вміти виконати GET/POST/PUT/DELETE запити через графічний інтерфейс
- Вміти передати JSON у тілі запиту й прочитати відповідь

## Підготовка викладача (перед заняттям)
Розіслати посилання на встановлення Postman заздалегідь (той самий принцип, що й з попередніми інструментами).

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Нагадати: досі API тестували через `curl` у терміналі — робочий, але не найзручніший спосіб (довгі команди, важко читати JSON у відповіді). Postman — графічний інструмент, що робить те саме набагато зручніше.

### 2. Коротка теорія (10–15 хв)
**Що таке Postman.** Програма для ручного тестування API: заповнюєте метод, адресу, заголовки, тіло запиту через зручний інтерфейс замість команд терміналу — і бачите відповідь у структурованому, підсвіченому вигляді.

**Встановлення:**
1. Перейти на [postman.com/downloads](https://www.postman.com/downloads/).
2. Завантажити інсталятор для Windows, запустити, встановити з налаштуваннями за замовчуванням.
3. При першому запуску можна створити акаунт (безкоштовно) або пропустити й користуватись без акаунта (з обмеженнями синхронізації, не критично для навчання).

### 3. Демонстрація / live-coding (15–20 хв)
Виконати наживо в Postman перші два запити з [`postman-requests-guide.txt`](src/040-postman/postman-requests-guide.txt):
1. Новий запит, метод GET, адреса `https://jsonplaceholder.typicode.com/users`, "Send" — показати масив користувачів у відповіді.
2. Метод POST, адреса `https://jsonplaceholder.typicode.com/posts`, вкладка Body → raw → тип JSON, вставити тестовий JSON, "Send" — показати статус `201 Created` і відповідь із доданим `id`.

### 4. Керована практика (20–30 хв)
Разом виконати решту запитів із [`postman-requests-guide.txt`](src/040-postman/postman-requests-guide.txt): GET неіснуючого ресурсу (404), PUT (заміна ресурсу), DELETE. Зберегти всі запити в одну Collection (кнопка "Save" при створенні запиту) — показати, як зручно повертатись до збережених запитів.

### 5. Самостійна практика / челендж (20–30 хв)
Кожен студент самостійно створює свою Collection у Postman із щонайменше 5 запитами до [jsonplaceholder.typicode.com](https://jsonplaceholder.typicode.com) (різні ресурси: `/albums`, `/photos`, `/todos`). Челендж: знайти запит, що повертає масив із сотнями елементів (`/photos` — 5000 фотографій) — подивитись, як Postman показує великий обсяг даних.

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: Postman стане постійним інструментом при розробці будь-якого backend API в майбутньому — саме так тестують власні API, перш ніж підключати до них frontend чи мобільний застосунок.

## Домашнє завдання (необов'язково)
Дослідити в Postman ще один публічний API (не jsonplaceholder) на вибір, зберегти щонайменше 3 запити в нову Collection.
