# HTTP детальніше

**Блок:** Блок 6. Основи вебу та фінальний проєкт семестру
**Код заняття:** `060-veb-http-final-proekt/020-http-detalno.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
Методи (GET/POST/PUT/DELETE), статус-коди, headers.

## Мета заняття
- Знати призначення основних HTTP-методів: `GET`, `POST`, `PUT`, `DELETE`
- Розуміти групи кодів статусу (2xx/3xx/4xx/5xx) і найпоширеніші конкретні коди
- Знати призначення найважливіших заголовків (`Content-Type`, `Content-Length`)

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Запитати: «HTTP-метод — це, по суті, ДІЄСЛОВО запиту: що ми хочемо зробити з ресурсом. Які дієслова ви б очікували для роботи з, наприклад, дописом у соцмережі?» (Прочитати, створити, змінити, видалити) — підвести до GET/POST/PUT/DELETE.

### 2. Коротка теорія (15–20 хв)
**HTTP-методи:**
- **GET** — отримати дані, нічого не змінюючи на сервері. Найчастіший метод (звичайне відкриття сторінки — це GET).
- **POST** — створити щось нове (новий запис, новий коментар). Дані передаються в тілі запиту.
- **PUT** — повністю ЗАМІНИТИ існуючий ресурс новими даними.
- **DELETE** — видалити ресурс.

**Групи кодів статусу:**
- **2xx** — успіх (`200 OK`, `201 Created` — після успішного `POST`).
- **3xx** — перенаправлення (ресурс переміщено в інше місце).
- **4xx** — помилка з боку КЛІЄНТА (`404 Not Found` — ресурс не існує, `400 Bad Request` — некоректний запит).
- **5xx** — помилка з боку СЕРВЕРА (`500 Internal Server Error` — щось зламалось на боці сервера, а не через ваш запит).

**Реальні перевірені приклади** (повний вивід — [`http-methods-status-codes.txt`](src/020-http-detalno/http-methods-status-codes.txt)):
```
GET /users/1      -> 200 OK
GET /users/9999   -> 404 Not Found (такого користувача не існує)
POST /posts       -> 201 Created (+ заголовок Location з адресою нового ресурсу)
```

**Заголовки (headers).** `Content-Type` — формат даних у тілі (`application/json`, `text/html`, `text/plain`). `Content-Length` — розмір тіла в байтах. Клієнт і сервер обмінюються десятками заголовків, але для базового розуміння досить цих двох.

### 3. Демонстрація / live-coding (15–20 хв)
Виконати наживо в терміналі (Git Bash, з блоку 4) команди з [`http-methods-status-codes.txt`](src/020-http-detalno/http-methods-status-codes.txt): `curl -i URL` для GET, `curl -i -X POST ... -d '...'` для POST — усі перевірені заздалегідь, дають точно такий вивід, як задокументовано.

### 4. Керована практика (20–30 хв)
Разом відкрити [http.cat](https://http.cat) — переглянути кілька кодів через жартівливі фото котів (`http.cat/404`, `http.cat/500`, `http.cat/301`) — гарний легкий спосіб запам'ятати найпоширеніші коди.

### 5. Самостійна практика / челендж (20–30 хв)
Кожен студент самостійно виконує в терміналі `curl -i` до кількох адрес [jsonplaceholder.typicode.com](https://jsonplaceholder.typicode.com) (наприклад `/posts/1`, `/posts/9999`, `/comments`) і записує отримані статус-коди. Челендж: спробувати `curl -i -X DELETE https://jsonplaceholder.typicode.com/posts/1` — який код повертається?

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: чому важливо повертати ПРАВИЛЬНИЙ код статусу (а не завжди `200`, навіть коли щось пішло не так) — клієнтський код (браузер, мобільний застосунок) часто приймає рішення саме на основі коду статусу, а не тексту повідомлення.

## Домашнє завдання (необов'язково)
Виконати `curl -i` до 5 різних публічних API (можна знайти список безкоштовних тестових API в інтернеті) і зібрати отримані коди статусу в один список.
