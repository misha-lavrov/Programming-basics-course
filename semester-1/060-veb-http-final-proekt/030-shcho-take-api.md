# Що таке API

**Блок:** Блок 6. Основи вебу та фінальний проєкт семестру
**Код заняття:** `060-veb-http-final-proekt/030-shcho-take-api.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
REST основи, формат JSON.

## Мета заняття
- Розуміти, що таке API і навіщо він потрібен
- Знати основи REST-підходу до побудови API
- Вміти читати структуру JSON

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Запитати: «Мобільний застосунок погоди не "вирощує" дані про погоду сам — звідки він їх бере?» Підвести до ідеї API — способу, яким одна програма "запитує дані чи дії" в іншої програми (сервера), не знаючи деталей її внутрішньої реалізації.

### 2. Коротка теорія (15–20 хв)
**Що таке API (Application Programming Interface).** "Інтерфейс", через який одна програма може звертатись до іншої — набір узгоджених правил: які запити можна робити, що вони повертають. Веб-API — API, доступний через HTTP (те, що вивчали два останні заняття).

**REST (Representational State Transfer).** Найпоширеніший підхід до проєктування веб-API: кожен ресурс (користувач, пост, товар) має свою адресу (URL), а дії над ним виражаються HTTP-методами: `GET /users/1` — отримати користувача, `POST /users` — створити нового, `PUT /users/1` — оновити, `DELETE /users/1` — видалити. RESTful API — API, побудований за цими принципами.

**JSON (JavaScript Object Notation).** Найпоширеніший формат даних для обміну через API. Реальний перевірений приклад — [`api-json-example.txt`](src/030-shcho-take-api/api-json-example.txt):
```json
{
  "id": 1,
  "name": "Leanne Graham",
  "address": {
    "city": "Gwenborough"
  }
}
```
`{ }` — об'єкт (пари "ключ": значення), `[ ]` — масив (список значень чи об'єктів), значення можуть бути рядками, числами, вкладеними об'єктами чи масивами. Дуже схоже на структуру класів із блоку 2 (об'єкт `address` усередині об'єкта користувача — так само, як клас міг мати поле іншого класу).

### 3. Демонстрація / live-coding (15–20 хв)
Відкрити в браузері [jsonplaceholder.typicode.com/users](https://jsonplaceholder.typicode.com/users) — показати масив `[ ]` з 10 об'єктами користувачів. Порівняти з [jsonplaceholder.typicode.com/posts/1](https://jsonplaceholder.typicode.com/posts/1) — інша структура (`title`, `body`, `userId`) — наголосити: кожен API має свою власну структуру відповіді, яку читають з документації конкретного API.

### 4. Керована практика (20–30 хв)
Разом дослідити ще кілька адрес API: `/users/1/posts` (усі пости конкретного користувача — вкладена адреса-ресурс), `/comments?postId=1` (фільтрація через параметри запиту після `?`). Обговорити структуру адрес.

### 5. Самостійна практика / челендж (20–30 хв)
Кожен студент самостійно досліджує [jsonplaceholder.typicode.com](https://jsonplaceholder.typicode.com) (на головній сторінці — список усіх доступних ресурсів: `/posts`, `/comments`, `/albums`, `/photos`, `/todos`) і занотовує структуру JSON для двох ресурсів на вибір. Челендж: намалювати (на папері), який Java-клас відповідав би структурі JSON із `/todos/1`.

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: чому розуміння API — критично важлива навичка навіть для тих, хто цікавиться саме backend-розробкою — саме backend найчастіше і СТВОРЮЄ такі API для frontend-застосунків чи мобільних клієнтів.

## Домашнє завдання (необов'язково)
Знайти в інтернеті список безкоштовних публічних API для навчання (["public APIs" списки на GitHub]) і дослідити структуру відповіді одного API на вибір, не пов'язаного з jsonplaceholder.
