# Простий HTTP-сервер на Java

**Блок:** Блок 6. Основи вебу та фінальний проєкт семестру
**Код заняття:** `060-veb-http-final-proekt/050-http-server-na-java.md`
**Тривалість:** 1.5–2 год
**Статус:** 🟢 розписано детально

## Опис
Демонстрація «під капотом» без фреймворків.

## Мета заняття
- Розуміти, як влаштований HTTP-сервер "зсередини", без фреймворків
- Вміти написати найпростіший сервер на Java, що обробляє кілька маршрутів
- Побачити свою власну відповідь у браузері й через Postman

## Структура заняття

### 1. Хук / мотивація (5–10 хв)
Запитати: «Досі ви лише НАДСИЛАЛИ запити (curl, Postman, браузер) — а що, якщо самим написати програму, яка ВІДПОВІДАЄ на запити?» Запустити [`SimpleHttpServer.java`](src/050-http-server-na-java/SimpleHttpServer.java) наживо, відкрити `http://localhost:8080/` у браузері — побачити власний текст, надрукований власним Java-кодом.

### 2. Коротка теорія (15–20 хв)
**`com.sun.net.httpserver.HttpServer` — вбудований HTTP-сервер JDK.** Без жодних зовнішніх бібліотек чи фреймворків (Spring Boot та подібні — тема семестру 2) можна створити працюючий HTTP-сервер прямо на стандартному Java:
```java
HttpServer server = HttpServer.create(new InetSocketAddress(8080), 0);
server.createContext("/", SimpleHttpServer::handleRoot);
server.setExecutor(null);
server.start();
```
`createContext("/", ...)` — реєструє **маршрут** (route): яка адреса обробляється яким кодом. `handleRoot` — метод, що отримує `HttpExchange` (об'єкт із деталями запиту й можливістю сформувати відповідь) і викликається щоразу, коли надходить запит саме на цю адресу.

**Формування відповіді:**
```java
byte[] bytes = body.getBytes("UTF-8");
exchange.getResponseHeaders().set("Content-Type", "text/plain; charset=utf-8");
exchange.sendResponseHeaders(200, bytes.length);
try (OutputStream outputStream = exchange.getResponseBody()) {
    outputStream.write(bytes);
}
```
Явно вказуємо статус-код (`200`), заголовок `Content-Type` (знайомий з заняття 020) і довжину тіла в байтах — саме ці елементи ми бачили в "сирих" HTTP-відповідях на попередніх заняттях, і тепер формуємо їх самі.

**Чому фреймворки існують.** Усе, що зроблено вручну в цьому прикладі (маршрутизація, формування заголовків, перетворення в/з JSON), у реальних проєктах бере на себе фреймворк (Spring Boot тощо) — саме тому семестр 2 присвячений саме їм. Але розуміння, що відбувається "під капотом", лишається корисним, коли щось працює не так, як очікувалось.

### 3. Демонстрація / live-coding (15–20 хв)
Розібрати [`SimpleHttpServer.java`](src/050-http-server-na-java/SimpleHttpServer.java) повністю: два маршрути (`/` — текстова відповідь, `/api/students` — JSON, побудований вручну як текстовий блок). Запустити, перевірити обидва маршрути в браузері, а потім і в Postman (заняття 040) — показати заголовок `Content-Type: application/json` для другого маршруту.

### 4. Керована практика (20–30 хв)
Разом додати третій маршрут — наприклад `/api/greeting`, що повертає персоналізоване текстове привітання.

### 5. Самостійна практика / челендж (20–30 хв)
Додати маршрут `/api/subjects`, що повертає (вручну побудований) JSON-масив назв предметів із бази даних блоку 5 (`Java`, `SQL`, `Git`) — не підключаючись до реальної бази, просто "захардкодивши" дані в код, як у `/api/students`. Челендж: змінити `handleStudents`, щоб при запиті на неіснуючий маршрут (наприклад `/api/teachers`, якого немає серед `createContext`) — переконатись, що сервер сам повертає `404 Not Found` без додаткового коду (`HttpServer` робить це автоматично для незареєстрованих маршрутів).

### 6. Рефлексія та підсумок (5–10 хв)
Обговорити: тепер, коли побачили HTTP-сервер "зсередини", як зміниться сприйняття фреймворків семестру 2 — вони не роблять нічого "магічного", лише автоматизують те, що щойно писали вручну.

## Домашнє завдання (необов'язково)
Додати до сервера маршрут, що приймає параметр з адреси (наприклад `/api/greeting` читає ім'я з query-параметра `exchange.getRequestURI().getQuery()`) і повертає персоналізовану відповідь.
